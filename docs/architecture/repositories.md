# Repositories

A repository is the only code allowed to touch a SQLAlchemy model directly. Everything above it — usecases, routers, tests — sees Pydantic DTOs.

## Rules

- **Plain concrete class, no `Protocol`/ABC.** Repositories are never swapped or mocked in tests, so an interface layer would buy nothing. `class UserRepository: def __init__(self, session: AsyncSession) -> None: ...`
- **Constructor takes `AsyncSession`** plus whatever else the queries need (e.g. `AppConfig` for a crypt key). Injected by dishka — see [di-providers.md](di-providers.md).
- **One method per operation**, named for what it does (`get_by_login`, `exists_with_role`, `update_fields`), not a generic CRUD passthrough.
- **Every read converts row → DTO** through an instance method `_to_dto(self, row)` / `_to_<entity>_dto(self, row)` — `XDto.model_validate(row, from_attributes=True)` unless a value is computed or JSON decoded. Nothing outside the repository ever holds an ORM instance.
- **Lookup naming:** `get_by_id` (and `get_by_id_for_update`) raises `NotFoundError`; a lookup that may miss is `find_*`; a `skip_locked` claim is `try_lock`. A list of ids filters through `core.db.filters.in_ids(column, ids)` (one `= ANY(array)` bind), never chunked `IN`. A method takes `now` from its caller when the caller already has one.
- **Writes call `session.flush()`, never `session.commit()`.** Commit is the usecase's job via `UnitOfWork` — see [usecases.md](usecases.md). Flush makes the write visible within the current transaction (autogenerated PKs, `onupdate=` columns) without ending it.
- **Public write methods take typed parameters**: one Create/Update DTO when the write sets a row's mutable columns, explicit typed arguments for a fixed transition (`mark_status_if(order_id, status, *, current, external_payment_id)`), nothing when the write has no variable data. Never `**kwargs`, never a bare `dict[str, Any]`, never the module's read DTO passed through unchanged. A private `_write(id, values)` helper shared by named transitions is fine (`BroadcastRepository`). `OAuthIdentityRepository.create` below and `UserRepository.create`/`update_fields` (`modules/users/repository.py`) are the reference shape.
- **`await session.refresh(row)` after mutating a row with server-computed fields** (defaults, `onupdate=`), before converting to DTO — otherwise the DTO conversion can lazy-load outside an awaited context.
- **Encryption/decryption at rest is not the repository's job.** Secret columns use `EncryptedString` (see [db-models.md](db-models.md)) — the repository reads and writes them like any other plain `str` attribute; encrypting/decrypting happens transparently at the column-type level, not via manual calls scattered across `_to_dto`/write methods.
- **Singleton-row tables** (`BotSettings`, `OAuthSettings`, `ShopSettings`, `AppearanceSettings`, `AccessSettings`, `CabinetAuthSettings`, `BotRequirements`, `EmailSettings`, `ReferralSettings`, `PricingSettings`, `LoyaltySettings`, `NotificationSettings`, `BackupSettings`, `ConnectGuideSettings`, `Blacklist`) use `core.db.singleton.SINGLETON_ID` (1) and get-or-create inside the repository method via `get_or_create_singleton()` — no DB constraint needed when the stakes are low enough (contrast with `User`'s `ux_users_single_owner`, see [db-models.md](db-models.md)).
- **Advisory-lock protected bulk replace flows** (delete-then-insert where interleaving would corrupt state) take the lock inside the repository method and document the arbitrary lock key inline.

## Example

```python
class OAuthIdentityRepository:
    def __init__(self, session: AsyncSession) -> None:
        self.session = session

    def _to_dto(self, row: OAuthIdentity) -> OAuthIdentityDto:
        return OAuthIdentityDto.model_validate(row, from_attributes=True)

    async def create(self, data: CreateOAuthIdentityDto) -> OAuthIdentityDto:
        existing = await self.session.scalar(
            select(OAuthIdentity).where(
                OAuthIdentity.user_id == data.user_id, OAuthIdentity.provider == data.provider
            )
        )
        if existing is not None:
            existing.external_id = data.external_id
            existing.external_login = data.external_login
            await self.session.flush()
            await self.session.refresh(existing)
            return self._to_dto(existing)

        row = OAuthIdentity(
            user_id=data.user_id,
            provider=data.provider,
            external_id=data.external_id,
            external_login=data.external_login,
        )
        self.session.add(row)
        await self.session.flush()
        return self._to_dto(row)
```

**Named exception:** `EventLogRepository.create(entry: EventLogEntryDto)` (`modules/event_log/repository.py`) keeps taking the module's read DTO directly, unlike the rule above. `EventLogEntryDto` isn't a read model with defaults being repurposed — every field is required and matches exactly what's written at creation, and no update path exists for a log entry (append-only audit log). A parallel `CreateEventLogEntryDto` here would duplicate the same field list with no behavioral difference. This is a deliberate exception, not an oversight — don't "fix" it to match the general rule.
